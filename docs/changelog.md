# Changelog

## Unreleased

- Behaviour change: `Dataset.viewer_url()` returns `None` with a warning when the viewer link loads another dataset's store, and `Dataset.view()` and `sddb-cli viewer-url` fail with `ValueError` (exit code 1) instead of opening it. The store id in the link (`.lamindb/<id>.zarr`, after decoding the link twice) is compared with the one in `zarr_url`. This hides 333 of the 5937 links in the 2026-10-28 catalog, the same ones the website hides.
- Behaviour change: `to_anndata()` with the default `gene_key=None` drops features whose var_name is missing or empty before it makes repeated names unique. Allen MERSCOPE tables hold 15 blank probes with missing names, and `to_anndata()` failed on them with `InvalidIndexError`. The existing warning names the member and now also gives the number of dropped features.
- Documentation: a "Guides from the paper" section with the two executed paper guides (H&E to expression, Novae domains across platforms), rendered from their stored outputs.
- The install instructions pin v0.1.2. `tests/test_docs_quickstart.py` holds the pinned tag in one constant, `ALPHA_TAG`, and fails when an install line in README.md or docs/ names another tag.
- `Catalog.dataset` also accepts a `canonical_key` such as `geo:GSM9778330`, after the full uid and the 16-character stem. The column is unique where it is set (5424 of 6087 datasets in the 2026-10-28 catalog); a null `canonical_key` cannot be looked up. A key that matches several rows raises `KeyError`, like an ambiguous stem. A new "Reproducible references" section in "From the website to Python" covers `Catalog(version=...)`, uids, stems and `canonical_key`.
- Documentation: the license text no longer calls the catalog's data redistributable without qualification. Every dataset is served, but 1031 of 6087 (17%) have no known license, and `license_redistributable` is false for them, which means the terms are not known. The default `license_set=None` applies no license filter; use `license_set=True` or `noncommercial=False` to filter. The `--redistributable` option help and the `redistributable` docstring say the same.
- Behaviour change: citations never drop a study silently. `cohort.citations()`, `citations_text()`, `sddb-cli cite` and the MCP `cite` tool used to keep only the studies with an entry in the published `citations.bib`, and wrote an empty file when none had one. Now every other study, and every dataset without a `study_id`, gets a fallback `@misc` entry keyed by its `study_id` or uid. The entry cites the dataset page on the website and carries the title, DOI, year, uids and license from the catalog. One study gives one entry however many datasets it has. One warning reports how many studies have a published citation and how many fallback entries were added. An empty cohort raises `ValueError` instead of writing an empty file. The new `sddb.citations.citation_entries` returns the BibTeX with the published and fallback counts apart, `citations_text()` still returns `(text, n)` with `n` counting every entry, `sddb-cli cite` prints "wrote N citations (M fallback) -> path", and the MCP `cite` tool returns `n_fallback` next to `n`. The website address is now `sddb.catalog.SITE_URL`, which the docs build also reads.
- Behaviour change: `Catalog.search` (and `query(search=...)`, `sddb-cli query --search` and the MCP tools) now lets a token match any facet. A row matches a token when any of its facet values matches it, so "liver" finds rows whose tissue is liver as well as rows whose study_id contains "liver". Before, a token that matched values in several facets had to match all of them, so `search("liver")` returned 0 datasets where `query(tissue="liver")` returns 306. Several tokens must all match, so "breast xenium" keeps rows that match both. A token that matches no facet value is ignored, and one warning names it. When no token matches anything, the result is still empty with a warning. The `matched` dictionary keeps its shape.
- New facets `preservation_method`, `magnification` and `collections`, the filters the website shows that `query` did not accept. `query(preservation_method="ffpe")` now works, and the new facets resolve aliases and give "did you mean" hints like the others. `sddb-cli query` has `--preservation-method`, and the MCP `query` tool takes `preservation_method`.
- Behaviour change: `summary()` counts distinct study_ids only. Rows without a study_id used to count together as one extra study. The new `n_without_study_id` key gives their number.
- The install instructions pin the alpha release: `pip install "spatialdata-db @ git+https://github.com/theislab/spatialdata-db-client@v0.1.1"`.
- Behaviour change: a string facet value in `Catalog.query` that is not in the catalog no longer returns an empty cohort silently. Values resolve through aliases first (case, spaces, hyphens and underscores are ignored, and `technology` accepts the `assay` label, so `technology="10x Xenium"` selects `Xenium`). A value that still does not resolve raises `ValueError` with a "did you mean" hint, for example "unknown technology value 'Xenum'; did you mean 'Xenium'?". `sddb-cli query` and `cite`, and the MCP tools, resolve values the same way and fail with the same message. A known value that matches nothing after the other filters still gives an empty cohort.
- New facets `hne_image` and `if_image` (True or False; null means unknown and matches neither) and `source`, the lowercased `study_id` prefix (`geo`, `hest`, `10x`, ...) that the client derives on load, so it shows in `to_df()` and `facets("source")`. New `query(redistributable=...)` keyword: True keeps datasets whose known license allows redistribution. The CLI has `--source`, `--hne-image/--no-hne-image` and `--redistributable/--no-redistributable`, and the MCP `query`, `cite` and `download` tools take `source`, `hne_image`, `if_image` and `redistributable`.
- Free-text `search` no longer matches the boolean facets, so a token such as "true" no longer empties the result.
- `to_anndata(spatial=...)` controls where `obsm["spatial"]` comes from. The default `"auto"` keeps a stored `obsm["spatial"]` that has no missing rows, and otherwise uses the centroids of the shapes element the table annotates, matched to rows by the table's `instance_key`. Allen MERSCOPE and MERFISH tables store no `obsm["spatial"]`, so their rows used to have missing coordinates after `to_anndata`; they now get the centres of their `cell_circles`. `"centroids"` always uses the shapes, and `"obsm"` keeps the old behaviour. Only the region's `shapes.parquet` is read, never images. A labels region counts as no source. One warning names the members that have no coordinate source, and their coordinates stay missing. With `"auto"` or `"centroids"`, `obsm["spatial"]` is set even when `elements` leaves out `"obsm"`.
- Behaviour change: `sddb.__version__` now comes from `v*` git tags only. The `catalog-YYYY-MM-DD` release tags used to set it, which gave versions such as `29.dev7+g50302e533`. Until the first `v*` tag exists, builds report `0.1.devN+g<sha>`.
- Behaviour change: `query(noncommercial=False)` now also requires a known license, so datasets with `license_unknown` true are no longer returned. It matches the website's "Commercial use OK" (3869 datasets in the 2026-10-28 catalog, where it used to return 4900). `noncommercial=True` and `None` are unchanged. `docs/cite-and-license.md` has a new license glossary.
- `freeze()` records the sha256 of the catalog file in `CohortManifest.source.sha256`. `verify()` fetches the catalog again and raises the new `CatalogChangedError` when a dated release changed after the freeze; for the rolling `catalog-latest` it only warns. If the catalog url cannot be fetched, `verify()` raises the new `CatalogUnavailableError` and does not fall back to a cached copy. `fetch_catalog` has a `fallback=` keyword for this (default True, so `Catalog()` still falls back). `from_manifest(m, catalog=...)` makes the same check against the catalog you pass. Manifests written before this change load with `sha256=None` and skip the check.
- `to_anndata(gene_key="ensembl")` and `gene_key="symbol"` put every member's genes under one id type before the join. Sources store genes differently (HEST keys them by Ensembl id, 10x by symbol), so the same gene used to land in two columns. Features without that id, such as control probes, are dropped, repeated ids keep the first, and one warning reports how many. The old name stays in `var["original_var_name"]`. The default `gene_key=None` leaves gene names as stored, and `to_anndata` now warns when members share fewer than half the genes of the smallest one. A member whose gene names repeat no longer makes `to_anndata` fail: the repeats get a `-1` style suffix and a warning names the member.
- `to_sdata`, `to_list` and `to_dict` accept `elements=` together with `dest=`. Only the named elements are copied to `dest/<uid>.zarr`, and `dest/manifest.json` records the copy with `status="partial"` and its `elements`. A later `download(dest)` fetches the whole store, and `Manifest.refetch` copies a partial entry's elements again. Manifests written before this change still load.
- Gene and feature lookups (`Catalog().genes`, `Catalog().features`, `sddb-cli genes`, `query --gene` and the MCP `genes`/`features` tools) stream the index in batches and keep only matching rows. They no longer load the whole index into pandas, so a lookup on the 128M-row gene index uses about 0.7 GB of memory instead of more than 40 GB.
- `Catalog.dataset` accepts the 16-character stem of a uid as well as the full uid; a stem resolves to the latest version.
- Downloads print their progress on stderr, and print nothing when the store is already cached.
- `sddb-cli download` ends with a summary on stderr: "downloaded N datasets (X MB) to <dest>", plus how many were already present.
- Documentation: the scverse-doc theme, a new landing page, and a "From the website to Python" page.
- `resolve(names, roles)` and `Dataset.resolve(roles)` map adapter roles (regexes) to a store's element paths, raising on no match or ambiguity.
- `table_centroids(sdata, table, image)` returns each table row's centroid in an image's scale-0 pixel space, through the spatialdata transformation graph.
- `to_anndata()` reads members in parallel (`max_workers`) and can copy catalog columns into `obs` (`obs_columns`), read only some table elements (`elements`, e.g. skip duplicate count layers) and map each member through a `TableAdapter` (`adapter`) before concatenation to bound memory; members the adapter skips are listed with their reasons in `uns["sddb"]`.
- Documentation site (this site), with a guided tour, task guides and generated API, CLI, MCP and catalog-column reference.
- `Catalog()` reads the rolling `catalog-latest` release and `Catalog(version=...)` now resolves dated releases (#25).
